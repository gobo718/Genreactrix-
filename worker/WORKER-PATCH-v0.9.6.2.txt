Genreactrix AI Worker v0.9.6.2

Purpose
- Stabilize component AI output after the v0.9.6.1 10-image stress test exposed invalid JSON and non-three-theme responses.
- Make the deployed Worker version directly verifiable.

Diagnosis boundary
- The screenshot error text "Theme provider response yielded ... unique valid selections instead of 3" is not present in current GitHub main, the checked v0.9.6.0 Worker source, or the v0.9.6.1 release package.
- Therefore that exact message cannot have been generated by those saved sources. v0.9.6.2 adds explicit build/version metadata so deployment identity can be verified instead of inferred.

Changes
- Moves AI generation from generic json_object mode to a component-specific JSON Schema for the first two attempts.
- Reactions schema requires every current canonical reaction and its confidence/reason pair.
- Themes schema requires exactly three theme objects.
- Description schema requires a non-empty description field.
- The Worker assigns promptVersions itself; the model no longer has to reproduce bookkeeping metadata.
- Adds strict post-validation after Cloudflare structured output.
- Themes must contain exactly three non-empty, case-insensitively unique labels.
- Retries malformed JSON, schema failures, missing fields, duplicate/short Theme sets, JSON Mode failures, and selected transient provider failures.
- Uses two JSON-Schema attempts followed by one bounded json_object fallback attempt.
- Successful results include provider.workerVersion, provider.build, and per-component attempt/mode diagnostics.
- /api/health now reports version 0.9.6.2, build component-json-schema-r1, and structuredOutput component-json-schema.
- Error JSON also carries workerVersion/build so the live deployment can be identified from the response body.

Intentionally unchanged
- Site remains v0.9.39.79.
- No client/browser retry is added in this bounded Worker-only patch; the observed "Failed to fetch" transport failure is a separate next target if it persists.
- Model remains @cf/meta/llama-3.2-11b-vision-instruct.
- ANALYSIS_KEY behavior is unchanged.
- No PrimFusion vocabulary, Director workflow, or report logic changes.

Gate
1. Deploy Worker v0.9.6.2.
2. Confirm /api/health reports version 0.9.6.2 and build component-json-schema-r1.
3. Run failed / next 10 with Reactions + Themes + Description.
4. Do not retry the full backlog unless the 10-image gate is clean or any remaining failure is isolated and understood.
